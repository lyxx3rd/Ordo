# 行级结构标签说明（V2：标题与正文分离）

每个非空原文行只选一个标签，不拆行、不改写。默认输出“行号:标签”的 JSON 对象。

| 标签 | 含义 |
| --- | --- |
| TEXT | 普通正文，默认值；包括带编号的要求、定义、解释、论述，以及标题或列表的续行。 |
| NEW_DOCUMENT | 新文件的起始标题。 |
| HEADER | 重复的非正文页眉、页脚，以及明确的独立页码行。 |
| INFO_PAGE | 封面、修订记录、编制/审核/批准、版本号等信息页中的元数据行。 |
| H1 | 正文一级章节的独立标题，本行只命名或概括后续内容，不承载具体正文。 |
| H2 | 正文二级章节的独立标题，要求同 H1。 |
| H3 | 正文三级及更深章节的独立标题，要求同 H1；超过三级统一封顶 H3。 |
| HN | 无任何章节编号或列表符号的独立短标题，起到局部小标题作用，本行不承载正文。 |
| POINT | 有明确列表或项目符号格式，并实际进行列举、分类、步骤或分点说明的列表起始行。 |
| TOC | 原文件目录中的行。 |
| TABLE | 实际表格中的行。 |
| APPENDIX | 明确的附录起始标记。 |

## 标题和带编号正文

先判断是否为标题，再判断层级。编号、字数、冒号、句号、加粗或缩进，都不能单独决定标签。

- 标题只命名或概括后续内容，不在本行给出具体要求、定义、解释或论述；标题式引导语与正文混在同一行时标 TEXT。
- 标题后仅附“无／（无）”说明章节为空时，仍标对应标题；若“无”单独占下一行，该行标 TEXT。标题附实质正文仍按混合行标 TEXT。
- 确认是标题后，根据全文结构及父级关系判断 H1/H2/H3。数字、中文章节和其他编号形式均可；不固定绑定编号形式与级别，也不要求编号连续。
- 编号深度不是标题深度；带编号的正文仍是 TEXT。HN 必须无章节编号或列表符号，不能作为编号正文的兜底标签。
- 真实标题超过三级时统一标 H3，不使用 HN；保留原编号，不把深层正文变成标题。
- 同级的真实章节标题应保持同级；同一编号序列中的正文仍是 TEXT，不要求与标题共享标签。

## 列表和正文

- POINT 必须同时有明确列表格式和实际的列举、分类、步骤或分点用途；编号、项目符号是证据，不是充分条件。
- 列表项可以是完整句子，可以很长，也可以带子列表；不能因为包含说明就标 TEXT。
- 独立的编号要求、术语定义或连续论述仍是 TEXT；仅连续出现多条定义或使用自然语言衔接，不构成列表。
- 列表起始行标 POINT；残留断行中的续行如果没有新编号或项目符号，标 TEXT，不制造新列表项。
- 无列表格式的列表引导句标 TEXT，不因后面有列表而标 POINT。

## 其他结构

- HEADER 包括重复页眉、页脚和明确独立的页码行；正文中的数量、比例、日期、页码引用不属于 HEADER。单次文件标题和普通章节标题不是页眉。
- INFO_PAGE 用于信息页或元数据区块。封面中的明确文件标题仍是 NEW_DOCUMENT，通用“程序文件”等类别字样用 INFO_PAGE；重复页眉优先 HEADER，不强制每份文件都有 NEW_DOCUMENT。实际表格行仍用 TABLE。
- TABLE 仅用于真实的行列表格，含单元格残留断行；正文外框、单独出现“|”的标题或引导语、没有稳定行列关系的流程动作串，不因此成为表格。
- 原目录条目用 TOC，不按目录里的编号改成 H1/H2/H3。
- 独立的“附录：”等起始标记用 APPENDIX，之后正常标正文、标题等，直到下一 NEW_DOCUMENT；没有独立附录标记时，按该行实际标题/正文用途标注，不虚构标记。
- 全局分析和上一批预测仅作上下文参考；不能覆盖本行的标题/正文/列表判断。无法确定且无明确特殊结构时，选 TEXT。
