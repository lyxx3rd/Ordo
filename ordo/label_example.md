# 行级标注示例（虚构）

以下文件和内容均为虚构。每个非空行的标签置于段首：[LABEL] 原文。各代码块是独立片段，说明文字不是待标注原文。

## 典型结构与关键边界

## POINT / TEXT 边界对照

章节式编号也可以用于列表：下面明确列举提交材料，标 POINT，不按编号深度标标题。

```text
[H2] 2.2 提交材料
[TEXT] 提交材料包括：
[POINT] 2.2.1 产品说明书。
[POINT] 2.2.2 检验报告。
[POINT] 2.2.3 风险管理报告。
```

相似编号下的独立要求用 TEXT；不只凭连续编号或“应、负责”等措辞判断，需结合是否构成明确列表。

```text
[H2] 2.2 材料管理
[TEXT] 2.2.1 申请部门应在提交前核对材料。
[TEXT] 2.2.2 审核部门应记录发现的问题。
```

明确列表中的要求仍是 POINT；外层列表项带子列表时仍保留 POINT，不自动改为 TEXT。无列表格式的引导句及列表续行用 TEXT。

```text
[TEXT] 验收应满足以下要求：
[POINT] 1）设备应运行正常。
[POINT] 2）材料应齐全，包括：
[POINT] a) 产品说明书。
[POINT] b) 检验报告。
[POINT] 3）负责人应签署验收记录，并确认
[TEXT] 所有问题已经完成整改。
```

## 特殊边界补充

明确的项目符号和字母列表可以承载具体要求或完整说明；仍需结合列举关系，不因包含“应”或句子较长而改为 TEXT。续行没有新列表标记时用 TEXT。

```text
[TEXT] 风险情形包括：
[POINT] ● 无法可靠估计发生概率的风险，应记录判断依据。
[POINT] ● 已知发生概率的风险，应结合后果严重程度进行评价。
[TEXT] 相应控制措施包括：
[POINT] - 使用者应在发现性能异常时停止使用，并联系维护人员。
[POINT] — 维护人员应检查故障原因，并记录采取的措施。
[TEXT] 验收条件如下：
[POINT] a) 当材料不齐全时，应记录缺失项目，并通知负责人
[TEXT] 在验收前补齐材料。
[POINT] b) 当材料齐全时，应核对签字和版本信息。
```

多行封面标题只在首行标 NEW_DOCUMENT，续行不代表新文件：

```text
[INFO_PAGE] 云杉咨询公司
[NEW_DOCUMENT] 现场设备安装与交付
[TEXT] 管理程序
[INFO_PAGE] 文件编号：YS-2026-013
```

没有独立附录标记、直接以章节标题开始时按标题标注；正文提及附录不触发 APPENDIX：

```text
[H1] 附录1：检查材料清单
[TEXT] 本节说明需要提交的检查材料。
[H2] 1.1 申请材料
[TEXT] 申请材料应由负责人签字。
[TEXT] 详细填写方法见附录1。
```

空章节保留标题；英文独立标题与具体要求也按相同规则区分：

```text
[H1] 4. 定义：（无）
[TEXT] 4. 定义：复验是整改后再次进行的验收活动。
[H1] 6. 相关文件
[TEXT] 无
[HEADER] 第 2 页，共 5 页
[H1] 5. Work procedure
[H2] 5.1 Preparation
[H3] 5.1.1 Document review
[H3] 5.1.1.1 Review scope
[TEXT] 5.1.1.2 Reviewers shall record missing documents.
```

表格根据真实行列关系判断，不取决于是否有竖线：下面的修订记录有稳定列对应关系，标 TABLE；含“|”的意见短标题后接普通正文，标 HN。

```text
[INFO_PAGE] 文件修订记录
[TABLE] 版本号    更改内容       更改人    更改日期
[TABLE] V1.1      增加验收要求   王某      2026-04-01
[TABLE] 并补充签字说明。
[HN] 申请方意见 | 检查方意见
[TEXT] 申请方认为材料已齐全，检查方要求补充签字记录。
[H2] 5.3 文件管理流程
[TEXT] 文件编写    文件审核    文件批准    文件发放
[TEXT] 文件更改
[TEXT] 文件销毁
```

表格中“并补充签字说明”是更改内容单元格的续行；末尾流程动作没有稳定的行列对应关系，用 TEXT，不凭多空格标 TABLE。超过三级的真实标题统一封顶 H3，不用 HN。
