# 全局结构分析

你将阅读一份完整文本，为后续的逐行结构标注提供全局背景。

只分析下列问题：

1. 文本是否拼接了多份独立文件？
2. 是否存在明确的文章标题？文章标题通常是独立的标题行，不是称呼、目录或正文标题。
3. 若未拼接多份文件且存在明确文章标题，抽取该标题的完整原文；否则填空字符串。不要给出行号；不要改写、概括或虚构标题。
4. 是否存在原文自带目录？
5. 是否存在表格？
6. 是否存在明确的附录标记，例如独立的“附录：”行？
7. 正文中是否存在一级标题？若存在，摘录 1 至 2 个真实出现过的完整一级标题作为示例。不要给出行号；不要改写、概括或虚构标题。
8. 用一句简短说明一级标题的主要形式。若无法确定，填空字符串。
9. 是否存在页眉？页眉是跨多个页面重复出现、通常位于页首的非正文信息；不要把只出现一次的文章标题或普通章节标题视为页眉。
10. 若存在页眉，给出一个页眉的具体示例。不要编造原文中没有的字段；若不存在，填空字符串。
11. 是否存在信息页？信息页是主要提供文档元数据、而非正文内容的页面或区块，例如封面、修订记录、编制/审核/批准信息、作者信息、版本号或生效日期；可以有多页。

不要做逐行标注，不要输出行号、范围、二级标题或三级标题示例，不要解释推理过程。

只返回合法 JSON，严格使用以下结构：

{
  "has_multiple_documents": false,
  "has_document_title": true,
  "document_title": "关于某事项的意见书",
  "has_page_header": false,
  "page_header_style": "",
  "has_information_pages": false,
  "has_toc": false,
  "has_table": false,
  "has_appendix": false,
  "has_h1": true,
  "h1_examples": ["一、示例一级标题"],
  "h1_pattern": "以中文序号‘一、’开头"
}

约束：

- 每个 has_* 字段只能为 true 或 false。
- document_title 必须是字符串；仅当 has_multiple_documents 为 false 且 has_document_title 为 true 时填写原文完整标题，其他情况返回空字符串。
- page_header_style 必须是字符串；仅当 has_page_header 为 true 时填写简短的页眉样式，其他情况返回空字符串。
- 信息页只判断是否存在，不要输出页码、行号或信息页示例。
- h1_examples 必须是数组；没有一级标题时返回 []。
- h1_examples 中只能包含原文完整行，最多 2 条。
- h1_pattern 只描述一级标题的可见形式，无法确定时为 ""。
